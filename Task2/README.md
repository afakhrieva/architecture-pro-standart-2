## Задание 2. FURPS+ таблица

| Код | Требования                                                                                                                                                                                                   | Комментарий                                                                                                                                                                                                                                                       |
|-----|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| F   | Функциональные (Functionality)                                                                                                                                                                               |                                                                                                                                                                                                                                                                   |
| F1  | На сайте: новый клиент видит список доступных депозитов с актуальными ставками, может подать заявку (Ф.И.О., телефон). | F3  | Заявки на депозит обрабатываются менеджером бэк-офиса в АБС. После подтверждения условий и открытия депозита клиент получает СМС.                                                                            | MVP предполагает ручную обработку, но с уведомлениями.                                                                                                                                                                                                            |
| F4  | На сайте: новый клиент видит предложение по кредиту (условия из кредитного конвейера). Может подать заявку (Ф.И.О., телефон). | F5  | В интернет-банке: клиент видит кредитные предложения + предодобренные предложения (на основе ранее рассчитанного скоринга). Подача заявки с указанием счёта, подтверждение СМС.                              | Предодобренные предложения ускоряют обработку.                                                                                                                                                                                                                    |
| F6  | Заявки на кредит из интернет-банка и сайта должны попадать в кредитный конвейер, обрабатываться в день подачи (для предодобренных – в течение рабочего дня).                                                 | Требование к срокам обработки.                                                                                                                                                                                                                                    |
| F7  | При изменении статуса заявки на кредит – СМС-информирование клиента.                                                                                                                                         |                                                                                                                                                                                                                                                                   |
| F8  | В отделении: менеджер работает с заявкой, которая уже была создана клиентом на сайте (идентификация по данным). Или создаёт новую заявку.                                                                    | Обеспечение непрерывности процесса (онлайн -> офлайн).                                                                                                                                                                                                            |
| F9  | Система должна логировать все действия клиента при подаче заявок (кто, когда, какие данные) для аудита и расследования инцидентов.                                                                           | Дополнительное требование. Чувствительные операции требуют аудита.                                                                                                                                                                                                |
| U   | Удобство использования (Usability)                                                                                                                                                                           |                                                                                                                                                                                                                                                                   |
| U1  | Интерфейс работы клиента должен быть максимально удобным, отклик операций – миллисекунды.                                                                                                                    | Сильное требование к UX и производительности.                                                                                                                                                                                                                     |
| U2  | Использовать единую дизайн систему (брендированные элементы, привычные цвета).                                                                                                                               | Требование к единому стилю приложений.                                                                                                                                                                                                                            |
| U3  | Для сотрудников бэк-офиса и кредитного отдела – возможность работы со ставками депозитов (сейчас в Excel). Нужен единый инструмент (желательно в АБС).                                                       | Удобство для внутренних пользователей.                                                                                                                                                                                                                            |
| U4  | В интернет-банке обеспечить автозаполнение полей (Ф.И.О., счёт для зачисления, сумма депозита/кредита – по умолчанию из профиля) при подаче заявки. Количество кликов для отправки заявки – не более 3.      | Дополнительное требование. Повышает скорость и удобство, снижает количество ошибок ввода. Клиенты (особенно молодые) ожидают минимальных действий.                                                                                                                |
| R   | Надёжность (Reliability)                                                                                                                                                                                     |                                                                                                                                                                                                                                                                   |
| R1  | Все сервисы должны работать 24/7, доступность 99,9% (включая интернет-банк и новые функции).                                                                                                                 | Бизнес-требование. Команда интернет-банка считает его невыполнимым при текущей архитектуре (один ЦОД, одна группа серверов, нет горизонтального масштабирования).                                                                                                 |
| R2  | При сбое в основном ЦОД необходимо переключение на резервный ЦОД. Интернет-банк должен оставаться доступным.                                                                                                 | Архитектурно значимое требование отказоустойчивости.                                                                                                                                                                                                              |
| R3  | АБС может масштабироваться только вертикально – это риск для надёжности при росте нагрузки. Нужно избегать прямых вызовов из интернет-банка к API АБС.                                                       | Ключевое ограничение, влияющее на архитектуру.                                                                                                                                                                                                                    |
| R4  | Система кредитного скоринга важна для работы банка, не должна перегружаться дополнительными предрасчётами.                                                                                                   | Требование к сохранению стабильности скоринга.                                                                                                                                                                                                                    |
| R5  | При сбоях в работе систем (АБС, кредитный конвейер, очереди сообщений) заявки клиентов не должны теряться. Должен быть механизм повторной обработки или сохранения в очереди до восстановления.              | Дополнительное требование. Заявки на депозиты и кредиты имеют финансовые последствия. Потеря заявки недопустима. Текущая пакетная интеграция не гарантирует доставку при сбоях. Требует внедрения очередей сообщений (например, Kafka) с подтверждением доставки. |
| R6  | Реализовать механизм идемпотентности подачи заявок (повторная отправка не создаёт дубликат).                                                                                                                 | Дополнительное требование. Защита от ошибок клиента или сбоев сети.                                                                                                                                                                                               |
| P   | Производительность (Performance)                                                                                                                                                                             |                                                                                                                                                                                                                                                                   |
| P1  | Отклик операций в интернет-банке – миллисекунды. Устранить текущие проблемы с загрузкой справочных данных (>1 секунды).                                                                                      | Требование к оптимизации запросов и, возможно, кэшированию.                                                                                                                                                                                                       |
| P2  | Подача заявок на депозиты и кредиты не должна создавать критическую нагрузку на АБС (БД перегружена). Использовать асинхронную передачу или очереди.                                                         | Архитектурное решение (например, Kafka).                                                                                                                                                                                                                          |
| P3  | Интернет-банк должен поддерживать равномерное распределение запросов между серверами и ЦОД (горизонтальное масштабирование).                                                                                 | Сейчас этого нет, требуется доработка.                                                                                                                                                                                                                            |
| P4  | Предусмотреть кэширование справочных данных (ставки, условия) на уровне интернет-банка для снижения нагрузки на АБС.                                                                                         | Решение проблемы долгой загрузки справочников.                                                                                                                                                                                                                    |                                                                                                                                                                                                                                                                   |
| S   | Поддерживаемость (Supportability)                                                                                                                                                                            |                                                                                                                                                                                                                                                                   |
| S1  | При доработках использовать существующие технологии (MS SQL, Oracle, .NET, Java, Python), где возможно. Новые технологии должны быть совместимы с текущим стеком и экспертизой в банке.                      | Ограничение на выбор технологий.                                                                                                                                                                                                                                  |
| S2  | Для межсервисного обмена (очереди сообщений) рекомендована Kafka. Но текущая версия платформы интернет-банка несовместима с Kafka – возможно, потребуется переход на микросервисы в рамках задачи депозитов. | Архитектурно значимое решение.                                                                                                                                                                                                                                    |
| S3  | Необходимо разработать документацию для дальнейшего расширения системы.                                                                                                                                      | Требование к документации.                                                                                                                                                                                                                                        |
| S4  | Избегать доработок со стороны подрядчика для функционала СМС – реализовать силами команды банка.                                                                                                             | Снижение зависимости от внешних подрядчиков.                                                                                                                                                                                                                      |
| S5  | Предусмотреть возможность горизонтального масштабирования интернет-банка (сейчас одна группа серверов).                                                                                                      | Для выполнения требований доступности и производительности.                                                                                                                                                                                                       |
| +R  | + Ограничения (Restrictions)                                                                                                                                                                                 |                                                                                                                                                                                                                                                                   |

| +R2 | Новые клиенты обязательно должны пройти идентификацию в отделении (законодательное требование).                                                                                                              | Влияет на процесс: онлайн-заявка-> визит в отделение.                                                                                                                                                                                                             |
| +R3 | Прямая работа интернет-банка с API АБС в новом процессе запрещена (из-за перегрузки АБС). | +R6 | При реализации микросервисной архитектуры для депозитов нужно обеспечить совместимость с остальными частями интернет-банка (поэтапный переход).                                                              | Ограничение на объём изменений.                                                                                                                                                                                                                                   |
